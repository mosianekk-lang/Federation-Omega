# EvidenceOps FEVX-MCOE

Permanent orchestration layer for all current and future EvidenceOps matters.

## Runtime contract

For every material directive:

1. Map the mission and dependencies.
2. Inspect actual authorised capabilities.
3. search for stronger native, composed or reusable routes.
4. Create or update one canonical mission state.
5. Build only missing, justified components.
6. Validate schemas, permissions, security and rollback.
7. Execute the strongest safe route.
8. Read back the target state.
9. Red-team the result.
10. Record maturity, proof, lessons and next action.

## EvidenceOps integration

- `POLICY.yaml` is the machine-readable policy.
- `mission_contract.schema.json` validates mission state records.
- `REGRESSION_TESTS.md` defines release-blocking behaviours.
- EvidenceOps doctrine and Secondary Brain capability registers mirror this policy.
- Bot-team roles inherit the specialist functions and collision controls.

## Standing boundaries

No secret exposure, no unsupported capability claim, no silent destructive action, no external communication or legal action without explicit release authority, and no completion claim without execution plus readback proof.
