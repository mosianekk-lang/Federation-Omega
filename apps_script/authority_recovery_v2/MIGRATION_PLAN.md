# Apps Script Authority Recovery v2 — Stable Migration Plan

## 1. Preserve serving state

Keep the supplied backup and current serving transport unchanged. Record the outer wrapper hash and every embedded-file hash. No destructive source rewrite, OAuth change, project rebinding or deployment cutover occurs during source admission.

## 2. Admit source and tests

Merge the bundle-aware authorization gate, exact lineage classifier, public gateway, private admin plane and hostile tests only after exact-head Airlock, leak and command-bus controls pass.

## 3. Create isolated provider projects

Create or reuse two distinct Apps Script projects only through authenticated provider administration:

1. minimum-scope public gateway with one router and no provider mutation capability;
2. private admin project bound to the canonical standard Cloud project and inaccessible as a public web app.

Do not copy the original monolith wholesale.

## 4. Bind external verification

Configure a fixed HTTPS verifier URL and exact hostname in the private admin project. The verifier must independently resolve provider receipts and effect permits from stable evidence references, echo a one-time challenge and bind transaction, action, target, request hash and expected source hashes. Same-project Script Properties are not independent authority anchors.

## 5. Negative ingress and replay canaries

Prove rejection of missing signature, invalid signature, stale/future timestamp, target mismatch, secret-bearing payload, reused nonce, reused permit, wrong transaction and changed mutation intent.

## 6. Provider identity and route proof

Read back:

- project ID and number `sov-hybrid-suite / 257649435135`;
- active principal fingerprint;
- OAuth consumer project equal to the canonical standard Cloud project for `scripts.run`;
- Apps Script API enabled and project access granted;
- API-executable deployment for the private dispatch route;
- current project content and deployment inventory;
- no inherited authority from `516699068552`, `516690968552` or `979287460558`.

## 7. Source-only reversible canary

Run a signed dry-run for a new non-serving canary file. Issue a one-use permit bound to the exact transaction, mutation-intent hash, current source hash, expected source hash and rollback reference. Apply, read back source hash, create an immutable version, then roll back and verify the original hash.

## 8. Deployment canary

Promote only a private/non-serving deployment. Require deployment-version readback and an independent action-specific semantic verifier. On any mismatch, restore both source and prior deployment version.

## 9. Serving cutover

Cut over only after transport, idempotency, replay, missed-run recovery, semantic execution, rollback and independent readback are proven equivalent or better. Keep the legacy route available for rollback until a sustained observation period confirms it is unused.

## 10. Retirement

Only after successful cutover and rollback canary may legacy privileged functions, static approval fields, raw authentication columns and duplicate handlers be removed from the serving project. Retirement of project `516699068552` remains a separate provider action and is not authorized by this source package.
