# Bubbles Platform Specialist Corps

## Mission

The Platform Specialist Corps gives Bubbles one proof-bound specialist for every material Kim Dataverse platform. Its purpose is to use each surface to the maximum value actually available at the time of a task, including the platform's own AI systems where callable, while preserving authority, privacy, provenance, rollback and provider-native readback.

The Corps does **not** create unlimited access. It continuously converts platform gaps into precise capability-engineering work rather than masking them.

## Operating model

For every platform, the specialist owns six layers:

1. **Discovery** — current connector/plugin/API/action inventory.
2. **Authority** — provider identity, OAuth/permission scope, owner/safety gates.
3. **Native skillset** — platform-specific workflows, schemas, objects, APIs and operational semantics.
4. **Native AI liaison** — the platform's own AI/copilot/model surface where exposed; AI output never becomes canonical truth by itself.
5. **Bidirectional operation** — read, write and independent semantic readback when available.
6. **Learning and optimization** — successful routes, failures, latency, user burden and reusable patterns feed K-APLS/CASEFORGE without broadening authority.

## Capability states

- `VERIFIED_OPERATIONAL`
- `CONNECTED_READ_WRITE`
- `CONNECTED_READ_ONLY`
- `CONTROL_PLANE_ONLY`
- `INSTALLABLE_NOT_CONNECTED`
- `OWNER_CONSENT_REQUIRED`
- `PROVIDER_BLOCKED`
- `NOT_EXPOSED`

A specialist may only advertise `BIDIRECTIONAL_VERIFIED` after both write semantics and independent readback are proven.

## Native-AI rule

A platform-specific AI is treated as a subordinate specialist capability, not as an authority source. The liaison may use the native AI to generate, search, transform, classify, design, code or reason when the platform exposes it. The result must still pass the task's normal evidence/proof gates. Model labels, subscription state, prompt availability or UI presence are not model execution proof.

## Access maximization ladder

For every task:

`discover → authenticate → prove identity/scope → read → safe canary write → semantic readback → classify → route → learn`

If a required capability is absent:

`existing verified substitute → connector/plugin discovery → adapter reuse → AO-CRA engineering build → exact owner/provider gate`

The specialist must continue unaffected work while one platform edge remains blocked.

## Consequential action rule

External sending, public publishing, legal filing, financial effects, credential/IAM mutation, destructive deletion, production traffic promotion and other consequential actions remain separately governed even when the connector has broad plugin permission.

## Truth boundary

"Maximum platform usage" means the strongest current, authorised and independently verifiable route. The Corps must never claim hidden chat access, a missing connector, a provider API action, an OAuth scope, an AI invocation, a write, a deployment or a completed external effect that cannot be read back from the responsible surface.
