# Bubbles — Applied AI Systems Architect Twin

Bubbles is Kim Kagiso Mosiane's proof-bound Applied AI Systems Architect twin.

The mission is not to create more architecture for its own sake. The mission is to turn the strongest existing systems into independently inspectable implementation evidence:

`code -> tests -> runtime -> provider execution -> provider readback -> deployment -> health -> persistence -> rollback -> observability -> user demo -> case study`

## Operating rules

1. Reuse before rebuild.
2. No source-only or design-only deployment claims.
3. No provider claim without provider-native readback.
4. No project-wide maturity inheritance from a narrower verified route.
5. No new meta-framework while an existing flagship has an executable proof gap that can be closed safely.
6. Every material blocker becomes an AO-CRA engineering build with a test and closure proof.
7. Prefer one boring, complete vertical slice over ten impressive incomplete architectures.
8. Preserve A1_INTERNAL authority and hold consequential external effects behind their existing gates.

## Flagship order

1. **CIOS** — full-stack/software architecture proof.
2. **eCertify ZA** — secure product and cloud-delivery proof.
3. **CASEFORGE-Ω / SCIENTIA** — real AI-provider, eval and readback proof.
4. **IPEP** — applied-AI/data-pipeline proof.
5. **ARCHITRON / Kim Dataverse** — event-driven automation and integration proof.
6. **K10 Canva Cinema** — visual automation proof.

The seed portfolio is deliberately conservative. It records only proof already supported by current source/runtime evidence and leaves deployment/provider/user-demonstration gates open where proof is missing.

## What Bubbles does

`BubblesArchitectTwin` derives the lowest defensible maturity state from explicit proofs. It refuses stage jumps. A provider call without independent readback remains `PROVIDER_EXECUTED_UNREADBACK`; a deployed claim requires runtime receipt, health, persistence and rollback; portfolio-demonstrable requires a real user journey and proof-safe case study.

Run the local snapshot with:

```bash
python -m bubbles.portfolio_loader
```

Run focused tests with:

```bash
python -m unittest tests.test_bubbles_architect_twin
```

## First live-build objective

CIOS is first because it already has durable state, a bounded HTTP runtime, transaction logic, a product surface, an end-to-end synthetic acquisition journey and provider qualification/canary contracts. Bubbles therefore targets the shortest remaining proof chain rather than rebuilding the product:

1. identify the authorised target execution plane;
2. bind the exact tested build/revision;
3. execute one harmless provider canary;
4. independently read back provider identity/target/state;
5. prove target health, persistence and rollback;
6. add structured observability;
7. run one user-visible end-to-end demo;
8. produce a proof-safe case study.

The same ladder is then reused for eCertify, CASEFORGE, IPEP, ARCHITRON and K10.
