# Performance Skillsets Harvested

## 1. Context engineering

Keep invariant instructions, tool definitions and policy in a stable prefix. Move current objective, deltas and source epochs into a small hot capsule. Retrieve cold doctrine by exact ID/hash. Reject required context that cannot fit the declared budget instead of silently truncating it.

## 2. Durable execution

Separate deterministic workflow state from failure-prone activities. Use append-only receipts, unique generation/slot identity, compare-and-swap heads, replay-safe idempotency and source epoch checks. Resume from the last verified receipt, never from the last optimistic claim.

## 3. Measurement engineering

Measure scheduled, admitted, started, tool, completed and published clocks separately. Record directly observed external attempts, retries, payload, proof success, invariant failures and harm signals. Never coerce missing metrics to zero.

## 4. Canary science

Use a fixed alternating baseline/candidate design, unique slots, one generation and predeclared thresholds. Require proof parity. Treat promotion and de-instrumentation as controller-owned terminal actions.

## 5. Stream reliability

Enforce byte/token limits before data crosses into chat. Filter and aggregate inside the executor. Quarantine oversized results, cap retries, avoid unchanged failed routes and checkpoint before rerouting.

## 6. Proof-state discipline

Score verified production evidence separately from design/readiness evidence. A local passing test proves the code path under test; it does not prove provider deployment, runtime behavior, performance gain or owner value.
