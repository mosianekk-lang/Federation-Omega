## Objective

Reduce the time between receiving a large mixed PDF and producing useful, source-grounded analysis, without weakening page coverage, provenance, privacy, or recovery behavior.

## Private corpus boundary

The qualification workload is a private 391-page mixed legal/evidence PDF. The source document stayed in the local execution environment. This public receipt intentionally omits the private file name, file path, corpus hash, and extracted text.

Environment: Linux x86_64, 5 logical CPUs exposed to the runtime, Python 3.13.5, PyMuPDF 1.26.7, Tesseract 5.5.0. Provider effects: zero.

## Incumbent vs challenger

Incumbent: FastDoc v1 from PR #1139.  
Challenger: FastDoc v2 staged successor.

Seven matched cold/warm repetitions were run with four native workers. The v2 interactive profile used 16-page bounded batches.

## Selective OCR court

The same 10 sparse pages were OCRed locally at 120 dpi.

- v1 PyMuPDF OCR-wrapper route: ~17.85 s total.
- v2 grayscale render + local Tesseract CLI route: ~8.98 s total.
- warm v2 selective OCR: all 10 pages cache-hit; no OCR subprocess repeated.
- after enrichment: 391/391 page mappings present and 391/391 pages had non-empty effective text.

This rejects whole-document OCR as the default route for this corpus.

## Downstream context court

Native extraction contains roughly 769,169 characters. FastDoc v2 builds query-specific context under a default 24,000-character hard ceiling using search hits and bounded neighbors. This avoids up to 96.88% of full-document native text injection on a query before model-side compaction.

Ten representative evidence queries all produced non-empty top-five retrieval results. This proves retrieval availability, not legal-answer accuracy.

## New receiver capabilities

1. Bounded completion-order page batches and early-result streaming.
2. Interactive vs throughput batch profiles.
3. Partial page-level resume instead of re-extracting the full PDF after incomplete state.
4. Cross-document extraction-payload reuse without page number in reusable payload identity.
5. Warm unchanged skip without index rebuild.
6. Selective OCR overlay separated from immutable native extraction payload identity.
7. Cache-first local OCR with a faster grayscale Tesseract CLI route.
8. Bounded context packs so downstream reasoning is retrieval-first, not full-PDF-dump-first.

## H9 decision

`PASS` for this receiver workload.

The challenger improves cold latency, warm latency, index cost, OCR wall time, restart behavior, and time-to-first-result while preserving the 391-page mapping and the same 10-page escalation floor. No measured protected floor regressed materially.
