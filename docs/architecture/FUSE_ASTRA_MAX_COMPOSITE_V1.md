# FUSE Astra Max Composite v1

Status: SOURCE_CANDIDATE / provider-neutral public-mechanism harvest.

## Objective

Adopt the strongest publicly documented GPT-6 Astra / ChatGPT Work / Codex mechanisms into the existing FUSE estate without pretending the current model is Astra and without creating a second mission, authority, scheduler, state, memory or proof root.

The operating mode is:

\`MAXIMUM_AUTHORIZED_CAPABILITY\`

This means FUSE removes unnecessary local throttles, goal dilution and avoidable serialisation when a safe machine route exists. It does **not** remove authorization, privacy, legal, safety, effect, source-fence or budget boundaries.

## Aggressive mode law

FUSE may increase reasoning depth, route fan-out, parallel ready-lane execution, computer-use autonomy and verification effort to the highest currently qualified level when:

1. the mission objective remains unchanged;
2. the route is current and callable;
3. privacy and authority permit the operation;
4. collision domains are clear;
5. cost/budget policy permits it;
6. unknown effects are reconciled before retry;
7. consequential decisions remain separately gated.

No provider limitation may silently shrink the canonical mission. A provider/model limitation is a route-local constraint unless every qualified route is exhausted.

## Astra provider cell

If a live GPT-6 Astra provider is current, callable, authorized and cost-qualified, the route portfolio may prefer it for complex reasoning, computer use, research, coding and professional artifacts.

If Astra is not callable, FUSE retains the harvested public mechanisms and routes them through other qualified models/tools. Mechanism adoption therefore does not depend on one provider.

The source profile never claims that GPT-5.6 Sol, another model, or the FUSE runtime itself has become GPT-6 Astra.

## Computer-use hierarchy

For an Astra-capable route:

1. code execution for complex/repetitive computer use where available;
2. FUSE typed Browser Control Plane / structured UI tools;
3. structured computer/mouse/keyboard tool;
4. semantic DOM + visual control;
5. bounded visual-coordinate fallback.

All mutating actions require semantic readback. Consequential website/desktop effects remain action-authority gated.
