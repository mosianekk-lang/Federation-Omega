# FUSE Creative Freedom Routing v1

## Purpose

Make creator intent the sovereign design input across FUSE/Federation creative work.

The user-facing design space is compiled independently of any single provider,
model, editor, export format, quota or UI. Platform constraints are treated as
execution facts. They may change the route, decomposition, representation or
residual capability build, but they may not silently rewrite the creator's goal.

## Global routing law

`CREATOR INTENT -> FUSE_CREATIVE_IR_V1 -> capability graph -> route tournament -> execute -> semantic readback -> proof`

For every creative/design mission:

1. Capture the complete objective, required modalities and non-negotiables before provider selection.
2. Preserve the objective byte-for-semantics through routing; provider/tool limitations cannot narrow it.
3. Convert provider constraints into one of: `ROUTE_AROUND | TRANSCODE | DECOMPOSE | BUILD_RESIDUAL | HOLD_EXECUTION`.
4. Prefer existing FUSE capabilities, local/private execution and provider-neutral contracts before new vendor dependence.
5. Use multiple providers or tools when composition gives a stronger result, but keep the editable master and canonical mission state FUSE-owned.
6. Treat formats as interchange surfaces, not source-of-truth masters.
7. Never require the owner to redesign around a provider UI or feature gap when a safe machine route exists.
8. A genuine legal, safety, privacy, authority or access boundary may hold execution, but the canonical creative objective remains unchanged and available for another lawful route.
9. No provider lock-in is permitted in the creative contract.
10. Production/publishing/external effects remain separately authority-gated and proof-gated.

## Platform independence does not mean boundary bypass

This architecture does not bypass platform safety rules, access controls,
licensing, legal restrictions or authority gates. It removes those constraints
from the *creative specification layer* and contains them in the execution
adapter layer.

## Scope

This is an additive routing/contract layer over SOVARA Creative, Formation,
CFBE/Hypercube, provider cells, FUSE Creative Studio and existing ProofOS
controls. It creates no second controller, truth store, memory root or scheduler.

## Proof boundary

Source admission proves only that creator intent is represented independently
from platform constraints and that deterministic routing classifications exist.
It does not prove live provider capability, provider effects, deployment,
publication, commercial value or whole-mission completion.
