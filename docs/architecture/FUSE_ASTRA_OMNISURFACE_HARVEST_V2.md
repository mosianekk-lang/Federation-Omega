# FUSE Ω∞ × Astra OmniSurface Fabric v2 — Deep CFBE Harvest

**Capture:** 2026-09-11 SAST  
**Mission:** Lock the GPT-6 Astra harvest into Federation source, then converge the currently connected and future provider estate behind one provider-neutral capability plane.  
**State:** SOURCE-ADMISSION CANDIDATE. No provider/API/IAM/traffic/credential or financial effect is claimed by this document.

## 1. Decision

Do not make Astra, Gemini, Copilot, Google Cloud, Canva, Adobe, GitHub, Luno, or any future vendor the Federation's control plane. FUSE remains sovereign over mission identity, authority, canonical state, completion, proof and continuity. Models and providers are replaceable processors and effect surfaces.

The new convergence path is:

`Owner → FUSE/N-OMEGA → MissionIR → Alpha-Omega/Formation → Adaptive Intelligence + OmniSurface Fabric → FDOF leases/idempotency → provider adapter/tool → provider-native readback → ProofOS/RealityGuard → KDV/Bible checkpoint`

## 2. Harvested external mechanisms

### GPT-6 Astra

Adopt: async tool calling, mid-turn steering, reasoning configuration updates, computer use, hosted shell/apply patch, Skills/MCP, large working context, prompt caching and strict tool-rich Responses routing. Preserve a cheaper Luna-class volume lane for low-consequence/high-volume work rather than routing everything to Astra.

### MCP 2026-07-28

Adopt the new stateless MCP core, header-routable calls, cacheable capability catalogs, hardened authorization, explicit task handles and trace propagation. Provider session state must not become Federation mission state.

### A2A 1.0

Use A2A for agent-to-agent discovery and collaboration; use MCP for tool/resource access. Both feed the same Federation capability contract and proof spine.

### Google Cloud + Workspace

Use Cloud Run/Jobs for scalable execution, Eventarc + Pub/Sub for event transport, Workflows for durable orchestration, and Workspace event/watch mechanisms where available. Apps Script remains the lightweight Workspace automation plane; the Apps Script API provides source/deployment management and `scripts.run` remote execution under user OAuth and a common standard Cloud project.

### Google AI Studio / Gemini

Treat Gemini as a diverse reasoning/multimodal/function-calling processor. Function calls become Federation tool intents; the external function still executes through an authorized adapter and must return provider/readback proof.

### GitHub + Copilot

GitHub remains code/provenance/CI/release control. Copilot custom agents become specialist coding cells with MCP tool access, but commits/PRs remain governed by the existing Airlock/ProofOS/CI chain.

### Canva

Canva's MCP surface can expose design creation/editing, asset/brand operations, library search, export and comments. Canva remains a derived creative surface, not a truth store.

### Adobe

Adobe Firefly Services and Creative Cloud/Acrobat surfaces provide generative and production APIs. Adobe joins the same creative capability contract as Canva, allowing routing by task, quality, cost and readback rather than brand preference.

### Microsoft Copilot

Copilot Studio can consume MCP servers and Power Platform connectors. Federation can therefore expose bounded FUSE capabilities outward through MCP while consuming Copilot specialist capability inward without surrendering policy or memory authority.

### Luno + LONA

Luno exposes REST, WebSocket market data and an MCP path. The existing Federation implementation is already deliberately observer-first. Preserve that. Luno and LONA are admitted only for observation, research, dataset normalization, backtesting and optimization in this convergence layer. No autonomous order, transfer or live-trading path is introduced.

## 4. New load-bearing contracts

1. **SurfaceDescriptor** — provider/product/protocol/capabilities/readback/effect ceiling/auth strategy.
2. **SurfaceAttestation** — provider identity + endpoint fingerprint + advertised protocols/capabilities + authority ceiling.
3. **MissionNeed** — capability request independent of provider.
4. **RouteChoice** — minimum sufficient multi-surface cover with no execution claim.
5. **AsyncCorrelation** — `mission_id ↔ mission_node_id ↔ FDOF lease ↔ provider call_id ↔ MCP/A2A task`.
6. **SteeringContinuation** — applies changed requirements without silently erasing completed work.
7. **ProviderEventEnvelope** — CloudEvents-style event normalization and trace correlation.
8. **Future surface admission** — signed/verified capability advertisement; no core-code rewrite needed for a new vendor.

## 5. Automatic route classes

- **Frontier cognition:** Astra for hard end-to-end work; Luna for cheaper volume; Gemini/Copilot as diverse specialists when their capability/cost/authority profile wins.
- **Workspace:** Gmail, Drive, Calendar, Contacts, Outlook and future SharePoint/Teams/Dataverse connectors.
- **Cloud/runtime:** Google Cloud, Windows plane, GitHub Actions and future runtimes through MCP/A2A/direct adapters.
- **Creative:** Canva + Adobe + native image/video systems.
- **Engineering:** GitHub + Copilot + Astra shell/apply-patch, always behind source tests and admission.
- **Capital intelligence:** Luno observation + LONA research/backtest only.

## 6. Future-proof connector law

A newly connected provider is not added by writing bespoke orchestration logic first. It publishes or is wrapped into a Federation surface passport. The fabric verifies identity, endpoint fingerprint, protocols, capabilities, effect ceiling and readback. If compatible, it becomes routable immediately at the maximum safe effect class proven by its attestation.

Preferred interoperability order:

`MCP 2026-07-28 → A2A 1.0 → Federation-native contract → connected plugin → direct REST/WebSocket adapter`

This order is a preference, not dogma; provider-native readback and lower total mission cost can win.
