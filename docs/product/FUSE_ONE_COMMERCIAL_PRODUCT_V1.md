# FUSE One Sovereign Workbench — Commercial Product v1

## Product

A Windows-first, local-first AI workbench that converts user goals into durable,
auditable work across local and approved connected surfaces.

## First paid customer

Technical founders, automation/ICT leads and trust-sensitive knowledge teams who
need AI to do consequential work but cannot accept opaque provider lock-in,
unverifiable "done" claims or cloud-only continuity.

## Customer promise

1. Install without administrator elevation where Windows permits per-user install.
2. Remain useful offline for the cold/local core.
3. Connect approved providers as replaceable processors, not sovereign controllers.
4. Resume long-running missions after interruption.
5. Show progress, authority and effect boundaries.
6. Read back consequential effects before claiming success.
7. Preserve evidence/proof receipts.
8. Support rollback/recovery.
9. Expose a trust/provenance view.
10. Measure owner/customer value rather than benchmark vanity.

## Initial package

- FUSE One Desktop — Windows user-scoped application.
- FUSE One CLI — deterministic/local operator surface.
- FUSE One Companion — optional web/mobile surface.
- FUSE Trust — proof, provenance and currentness view.
- FUSE Connect — governed provider/connector adapters.

## Commercial differentiators

- provider-neutral capability routing;
- local/offline cold path;
- proof-before-claim execution;
- durable mission continuation;
- semantic readback instead of transport-success inference;
- authority/effect previews;
- Hypercube bottleneck-to-product-improvement loop;
- no mandatory proprietary model for cold-state operation.

## Release ladder

SOURCE -> TESTED -> TWIN -> SUPPLY_CHAIN -> CANARY_READY -> PROVIDER_VERIFIED ->
DEPLOYED -> OPERATIONAL_VERIFIED -> VALUE_VERIFIED

## Hard commercial gate

The product is not COMMERCIAL_RELEASE_READY until both the Production Genesis
proof ladder and Product Release terminal proofs are complete.

A green repository, signed installer, deployed website or provider canary is only
scoped progress.

## Current high-value Hypercube bottlenecks

1. runtime-convergence stack admission;
2. signed per-user Windows installer lifecycle;
3. owner-PC native execution/readback;
4. architecture entropy / customer-facing simplification;
5. authorized native interaction binding.

These bottlenecks must produce reusable product capability rather than one-off fixes.
