# SOVARA Creative Commercial Value Engine v1

## Mission

`SC-COMMERCIAL-VALUE` makes commercial value a co-equal production criterion with operational value and owner usability.

SOVARA Creative is not considered a production winner merely because it generates attractive assets, runs quickly, or reduces technical burden. A repeated production cohort must also produce evidence-backed business value through an appropriate mission-specific metric contract.

The target flywheel is:

```text
OWNER INTENT / BUSINESS OBJECTIVE
  -> CREATIVE MISSION
  -> BRAND / CONTENT CONTEXT
  -> CREATE / ADAPT / PRODUCE
  -> REVIEW / QA / APPROVE
  -> PACKAGE / ACTIVATE THROUGH AN AUTHORISED ROUTE
  -> PROVIDER-NATIVE READBACK
  -> CHANNEL / ASSET PERFORMANCE
  -> UNIT ECONOMICS / OWNER BURDEN
  -> CFBE + OMEGA-SCIENTIST LEARNING
  -> CREATIVE / ROUTE / CAPABILITY IMPROVEMENT
  -> NEXT MISSION
```

## Commercial-frontier pattern

The living CFBE Meta benchmark should compare SOVARA Creative with a best-of-breed composite rather than a vendor average. Current comparator families include Adobe Creative Cloud / GenStudio, Canva Magic Studio / Canva AI, Runway, DaVinci Resolve, Descript, Celtra and Smartly.

Publicly documented frontier patterns relevant to SOVARA include:

- content-supply-chain integration from on-brand creation through review/approval, reuse and performance analysis;
- conversational/agentic idea-to-complete-work experiences with brand memory;
- creative generation connected to media activation and performance intelligence;
- predictive pre-launch creative evaluation;
- reusable generative workflows exposed as callable endpoints;
- multi-channel personalization and variant production.

SOVARA should harvest public engineering/product patterns, not proprietary implementation details. Frontier evidence never grants provider authority or proves that SOVARA has reproduced a vendor's behavior.

## Three mandatory value classes

Production-value promotion requires all three classes:

### Commercial

Examples:

- attributed revenue;
- contribution margin;
- ROAS;
- conversion rate;
- CPA/CAC where relevant;
- revenue per published asset;
- asset longevity/reuse with demonstrated business impact.

### Operational

Examples:

- time to deliverable;
- publication/activation success rate;
- recovery time;
- throughput;
- provider/tool reliability;
- cost per approved asset.

### Usability

Examples:

- owner interventions;
- owner minutes;
- manual tool switches;
- technical corrections;
- approval burden.

A gain in one class cannot silently compensate for failure of a mandatory class.

## Mission economics

`MissionEconomics` records direct economics supplied by trusted telemetry:

- currency;
- attributed revenue;
- provider cost;
- external tool cost;
- owner labour cost;
- other direct cost;
- approved asset count;
- published asset count.

Derived metrics include total cost, contribution margin, margin rate, cost per approved asset and revenue per published asset.

The model may not invent these values. Revenue/cost/performance truth must come from owner-entered verified records or provider/platform readback.

Loss-making experiments are valid evidence and must be preserved. A negative contribution margin is not rounded away or reclassified as success.

## Zero-baseline rule

A zero or negative baseline does not create a multiplicative improvement claim.

For example, moving from zero revenue to some positive revenue may be valuable, but it is not truthfully described as `10x` because the ratio is undefined. The engine records the absolute improvement and waits for a positive measured baseline before claiming a ratio.

Likewise, `zero revenue -> zero revenue` cannot satisfy the default commercial production gate. Default revenue and contribution-margin contracts require a positive candidate value.

## Production value gate

The value gate is fail-closed:

```text
METRICS PRESENT
  -> METRICS VERIFIED
  -> NO CRITICAL/HARD REGRESSION
  -> PROVIDER-NATIVE READBACK
  -> REPEATED SUCCESS
  -> OPERATIONAL TARGETS MET
  -> USABILITY TARGETS MET
  -> COMMERCIAL TARGETS MET
  -> PRODUCTION_VALUE_CANDIDATE
```

`PRODUCTION_VALUE_CANDIDATE` is still not an unconditional deployment authority. The surrounding SOVARA/Federation authority envelope decides consequential production changes.

## Default scorecard

The source package supplies a conservative default repeated-mission scorecard:

- contribution margin — commercial hard gate;
- attributed revenue — commercial;
- time to deliverable — operational;
- publication success rate — operational hard gate;
- owner interventions — usability;
- owner minutes — usability.

Mission-specific scorecards may replace revenue/margin with stronger applicable commercial measures such as ROAS, CPA or conversion, but the COMMERCIAL class may not be silently removed from production promotion.

## Production convergence

The intended path to estate-wide live production is:

```text
SOURCE / CI
  -> CURRENT PROVIDER / IDENTITY READBACK
  -> PRIVATE ZERO/LOW-RISK RUNTIME
  -> BOUNDED END-TO-END CREATIVE CANARY
  -> ASSET / PACKAGE READBACK
  -> BOUNDED CHANNEL ACTIVATION WHERE AUTHORISED
  -> PERFORMANCE + ECONOMICS TELEMETRY
  -> FORCED FAILURE / RECOVERY CANARY
  -> REPEATED COHORT
  -> SLO / COST / VALUE SOAK
  -> PRODUCTION VALUE GATE
  -> CONTROLLED FEDERATION EXPANSION
```

Full-estate expansion must be progressive. One successful provider route may not be generalized to Canva, Gemini, Google Cloud, OpenRouter, publishing channels, or every Federation node without same-surface proof.

## Truth boundary

This source slice defines and tests commercial-value contracts. It does not itself:

- deploy a Google Cloud runtime;
- call a model/media provider;
- mutate Canva designs;
- publish a campaign;
- spend advertising budget;
- attribute real revenue;
- prove repeated production success;
- prove soak or commercial value.

Those are later provider/behavior/value proof gates.
