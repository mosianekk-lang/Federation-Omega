# SOVARA Creative Sovereign Studio v1

## Purpose

This source slice adds two bounded internal capabilities to the existing SOVARA Creative daughter system:

1. `SC-SOVEREIGN-STUDIO` — planning for private creative execution planes when privacy, task class, or provider compatibility requires owner-controlled execution.
2. `SC-CAPABILITY-FOUNDRY` — reuse-first compilation of missing technical capabilities into source candidates that must cross tests, CI, authority and provider-proof gates before deployment.

It does not deploy Google Cloud infrastructure, call a model provider, publish media, mutate credentials, or claim provider/runtime maturity.

## Federation capability inheritance

The adaptive foundry is designed to reuse before inventing. Preferred reusable capability classes include:

- SOVARA provider execution and provider recovery
- Formation Ω route formation and convergence
- CFBE-Ω challenge/benchmark/value logic
- Failure-to-Operational-Win v2 recovery and failure-to-engineering-gene concepts
- Ω-AUTOFIX receiver patterns
- EvidenceOps Innovation and Algorithm Foundry
- ProofOS Ω admission/proof selection
- Bubbles and Sentinel Ω reliability controls
- Living State
- Universal Effect / Provider Proof patterns

The foundry does **not** inherit authority from these systems merely by referencing them.

## Adaptive skill loop

```text
NEED
  -> CAPABILITY DISCOVERY
  -> REUSE / EXTEND / COMPOSE / INVENT
  -> SOURCE CANDIDATE
  -> DETERMINISTIC TEST
  -> CI ADMISSION
  -> AUTHORITY CHECK
  -> DEPLOY
  -> PROVIDER-NATIVE READBACK
  -> REGRESSION / SOAK
  -> LEARNING
```

Invented code may not self-promote from idea/source directly to deployment. The implementation deliberately reports `can_deploy=False` until an explicit deployment-authorized or provider-proven admission state exists.

## Studio execution planes

The initial planner distinguishes:

- deterministic processing
- mainstream/frontier model routes
- private owner-controlled model cell
- creative-tool routes
- non-generative private processing

Sensitive private assets and mature/adult-oriented work are routed private-first at the planning layer. Secret material is routed to non-generative private processing, not to generative model planes.

## Owner experience

The design goal is `ordinary English / reference asset -> professional production plan`, with technical details hidden unless they materially affect a creative choice, privacy boundary, authority transition, or proof claim.

## Proof boundary

Current branch state is SOURCE_CANDIDATE only. Tests in `tests/test_sovara_creative_sovereign_studio.py` cover private-first routing, secret non-generative handling, reference-vault gating, reuse-before-invent strategy, and deployment fail-closed behavior. Hosted CI admission remains a separate gate.
