# Federated Cognitive Institution Omega v1

## Purpose

FCI Omega is the next additive layer above MCE, AMCF and SOE Omega. It turns mission execution and strategic portfolio intelligence into an authority-bounded institutional operating model without replacing the existing Federation systems.

The stack becomes:

```text
Human owner / final consequential authority
  -> SOVARA constitutional authority + proof control plane
  -> FCI Omega institutional cognition
  -> SOE Omega strategic objective ecology
  -> AMCF proof-directed mission autonomy
  -> MCE deterministic closure kernel
  -> specialist Federation systems / provider adapters
  -> independent semantic readback
```

FCI Omega is intentionally a thin coordination and governance layer. It reuses the existing SOVARA constitutional runtime, Formation Omega, Failure-Win, KAIO, JARVIS, CFBE, TruthGrid, ChatBridge, DPF and specialist systems instead of creating a second sovereign control plane.

## Institutional organs

FCI models six bounded institutional roles:

- Proposer — produces hypotheses and candidate decisions.
- Builder — constructs bounded implementations.
- Falsifier — actively seeks failure and counterevidence.
- Verifier — checks independent proof and semantics.
- Auditor — checks lineage, policy and institutional consistency.
- Steward — maintains continuity and institutional memory.

No role can self-certify consequential completion. Roles do not inherit provider authority from one another.

## Constitution Kernel

Every institutional proposal is evaluated before deliberation. Core invariants include:

- proof cannot be promoted beyond the surface and state verified;
- delegated authority can narrow but cannot silently expand;
- consequential owner intent cannot be rewritten without the owner;
- proposer/builder/executor self-certification is prohibited;
- consequential change requires rollback or an explicit owner irreversibility decision;
- correction and supersession preserve history.

The public-safe implementation defaults to `A1_INTERNAL` and does not execute provider effects.

## Evidence-Weighted Council

FCI does not use naive majority voting. Council weight is bounded by:

- evidence quality;
- historical calibration;
- confidence as a secondary factor;
- independence-domain diversity.

Multiple members from the same independence domain are discounted so that repetition does not masquerade as corroboration. A critical falsifier or verifier veto holds the decision even if the weighted majority supports it.

Dissent is preserved in the decision receipt rather than erased.

## Multi-timescale planning

Institutional objectives operate on four horizons:

- Tactical
- Operational
- Strategic
- Generational

The scheduler explicitly prevents long-horizon starvation. When capacity permits, every populated horizon receives representation before remaining slots are filled by weighted priority. Objective age increases priority so strategically important work cannot be postponed indefinitely by short-term urgency.

## Robust Scenario Planner

FCI uses minimax-regret planning rather than optimizing for one predicted future. Candidate options are evaluated across multiple scenarios, then adjusted for:

- maximum regret;
- mean regret;
- irreversible risk;
- evidence strength.

This biases the institution toward strategies that remain acceptable under uncertainty instead of brittle plans that win only when one forecast is correct.

## Policy Evolution Lab

Policy evolution is staged:

```text
CANDIDATE -> SHADOW -> CANARY -> ADOPTED
```

Promotion cannot skip a stage. Canary/adoption requires measured gain, no regression and rollback proof. Adoption additionally requires two independent replications. Consequential policy adoption remains owner-gated.

## Recursive Improvement Gate

Self-improvement is allowed only when all of these are true:

- measured candidate score exceeds baseline;
- no hard regression exists;
- improvement is independently reproduced;
- rollback is verified;
- authority changes, if any, have explicit owner approval.

FCI therefore supports recursive capability growth without allowing self-granted authority or self-certified improvement.

## Fractal delegation

Sub-institutions can be created with narrower or equal authority and explicit scope. A child cannot have a higher authority ceiling than its parent. This enables large-scale decomposition without authority leakage.

## Institutional Immune System

Anomalies are contained by affected domain rather than freezing unrelated work. A federation-wide freeze is reserved for a high-confidence critical anomaly that actually spans the complete declared federation domain set.

Local faults therefore isolate locally while independent safe work continues.

## Institutional Memory

Institutional cycles are appended to a hash-chained event ledger. Corrections add new events; they do not rewrite prior history. The ledger is public-safe and provider-neutral in this source release.

## High-scale operating loop

```text
owner intent
  -> constitutional preflight
  -> evidence-weighted deliberation + dissent
  -> multi-timescale objective selection
  -> robust scenario choice
  -> SOE portfolio allocation
  -> AMCF/MCE execution
  -> independent verification
  -> measured outcome
  -> policy/improvement lab
  -> institutional memory
  -> next cycle
```

## Proof boundary

FCI Omega v1 is source/control logic only until hosted admission and runtime proof exist. It does not establish provider deployment, credentials, browser/native-host installation, current-chat capture, external communications, financial actions, 24x7 service, resilience/soak or Fully Established maturity.
