# SOVARA Creative CFBE Meta-Evolution v1

## Purpose

`SC-CFBE-META` makes continuous frontier benchmarking part of SOVARA Creative itself. It compares the system against a **best-of-breed composite frontier** drawn from current public evidence about leading creative and production suites, then turns material gaps into falsifiable Ω-Scientist experiments and proof-gated engineering candidates.

This is not a vendor-cloning programme. A competitor capability is evidence that a useful production pattern exists; it is not authority to copy proprietary implementation or infer confidential practices.

## Initial comparator families

The initial public comparator families are:

- Adobe Creative Cloud / Firefly
- Canva Magic Studio / Canva Video
- Runway
- DaVinci Resolve
- Descript

The set is intentionally extensible. CFBE may add or retire comparator suites as the public frontier changes. Freshness is required; stale observations are not silently reused.

## Best-of-breed composite

SOVARA Creative is compared to the strongest evidenced capability per benchmark dimension, not to a vendor average.

```text
PUBLIC FRONTIER CENSUS
  -> FRESHNESS CHECK
  -> DIMENSION NORMALIZATION
  -> BEST OBSERVED CAPABILITY PER DIMENSION
  -> COMPOSITE FRONTIER
  -> SOVARA ARCHITECTURE SCORE
  -> SOVARA PROOF-ADJUSTED SCORE
  -> GAP / ADVANTAGE MAP
```

Core dimensions include director experience, multistep orchestration, reference recreation, multimodal generation, professional finishing, collaboration/review, cross-channel packaging, tool routing, private sovereignty, automated recovery, adaptive capability creation, proof/readback, owner burden, time-to-deliverable and value learning.

## Ω-Scientist loop

Material gaps become preregistered experiments with competing hypotheses, predictions, falsifiers, a primary metric, benchmark references and a rollback condition.

```text
GAP
  -> COMPETING HYPOTHESES
  -> PREREGISTRATION
  -> FORMATION ALTERNATIVES
  -> CFBE CHALLENGE
  -> CAPABILITY FOUNDRY REUSE/EXTEND/COMPOSE/INVENT
  -> SOURCE CANDIDATE
  -> DETERMINISTIC TEST
  -> EXACT-HEAD CI
  -> BOUNDED CANARY
  -> PROVIDER-NATIVE READBACK
  -> REPEAT / SOAK
  -> VALUE MEASUREMENT
  -> PROMOTE OR REJECT
  -> CREATIVE BIBLE + LEARNING UPDATE
```

The scientist lane has proposal authority only. It cannot widen permissions, deploy code, spend money, publish content, or promote a candidate by declaration.

## 10x rule

SOVARA Creative does not use `10x` as a decorative score.

A 10x target is permitted only where a positive measured baseline and meaningful ratio metric exist. Examples include:

- owner technical interventions per mission — target <= 10% of baseline
- tool switches required from the owner — target <= 10% of baseline
- recovery time after a route failure — target <= 10% of baseline
- time from reference upload to production-ready plan — target <= 10% of baseline
- time from detected frontier gap to tested candidate — target <= 10% of manual R&D baseline
- throughput, where safely scalable — target >= 10x baseline

For bounded quality dimensions where '10x quality' has no honest mathematical meaning, the target is `FRONTIER_PLUS`: meet or beat the strongest evidenced frontier while preserving reliability, privacy, proof and owner control.

## Promotion gate

An evolution candidate cannot become a default production behavior until all applicable gates are satisfied:

1. current public benchmark evidence exists;
2. Ω-Scientist experiment is preregistered;
3. no critical regression is present;
4. deterministic tests pass;
5. exact-head CI admits the source;
6. consequential/provider effects have provider-native readback;
7. repeated success is demonstrated;
8. value gain is measured;
9. rollback remains available.

Source/design success never inherits runtime/provider/value maturity.

## Current proof boundary

This v1 source slice implements deterministic benchmark/evolution contracts only. It does not itself perform web research, schedule recurring benchmark sweeps, deploy provider runtimes or autonomously mutate production. Live recurring benchmarking and automated upgrade execution require their own admitted runtime, authority, source provenance and readback.
