## 1. Mission

CANVA Ω-MAX converts proof-bounded Federation knowledge, evidence, architecture, missions and outcomes into high-quality visual communication without creating a parallel truth store or authority plane.

Its purpose is to make complex Federation work easier to see, understand, teach, decide, audit and reuse.

The target is not decorative slides. The target is **visual intelligence**.

## 2. Constitutional boundary

Canva is a presentation and design plane.

It may visualise verified information from authorised Federation sources, but it does not become the canonical evidence, mission-state, authority, capability or proof store.

A polished diagram never strengthens the epistemic status of the source claim.

The compiler must preserve the distinction between:

- doctrine;
- implementation;
- local or source tests;
- connector/provider readback;
- behavioural proof;
- longitudinal human value.

The visual maturity legend is:

`D0 Doctrine -> I1 Implemented -> R2 Runtime/Readback -> B3 Behaviour -> V4 Longitudinal Value`

Only the strongest actually proven state may be displayed as current.

## 5. Surface router

The system should choose the strongest communication surface rather than forcing every task into a presentation.

### Presentation

Use for sequential explanation, executive briefing, teaching, proposals, pitches and guided narrative.

### Report

Use for findings, evidence, audits, charts, structured analysis and decision support.

### Infographic

Use when one concept, system, process or comparison should be understood quickly.

### Poster

Use for architecture, control maps, maturity maps, wall references and whole-system views.

### Canva Doc

Use for collaborative text-first knowledge with rich visual structure.

### Whiteboard

Use for exploratory systems mapping and large relationship spaces where supported.

### Visual Atlas

Use for large knowledge bodies such as the Next Frontier Bible, EvidenceOps corpora, platform architectures and system universes.

### Design System

Use to preserve reusable patterns, visual legends and layout grammar.

## 6. Visual grammar

Do not copy paragraphs into rectangles.

Compile the information into a visual structure.

- Architecture -> layered system map / network map.
- Process -> flow / lifecycle / state machine.
- Science -> competing hypotheses / causal graph / falsification map.
- Evidence -> proof graph / source chain / claim-state model.
- Maturity -> D0/I1/R2/B3/V4 ladder.
- Governance -> authority rings / gates / boundaries.
- Continuity -> timeline / ledger / restore graph.
- Failure learning -> closed-loop failure-to-win system.
- Value -> human-outcome / owner-burden scorecard.
- Options -> comparison matrix / decision landscape.
- Large corpus -> atlas / map / volume architecture.

## 7. Three-level explanation standard

Major concepts should support three reading depths.

### 10-second view

The central idea should be immediately legible.

### 2-minute view

Major components, relationships and consequences should be visible.

### Expert view

The source, proof limits, cross-references, maturity and operational details should remain inspectable.

High expert depth must not destroy first-glance clarity.

## 14. Failure-to-Operational-Win integration

Visual failures become learning events.

Examples:

- text too dense;
- visual hierarchy unclear;
- source meaning distorted;
- diagram aesthetically attractive but informationally weak;
- maturity state visually overstated;
- owner asks repeatedly for more power/detail;
- design is inconsistent across volumes;
- provider operation fails or loses edits.

The response is:

`DETECT -> PRESERVE -> MODEL CAUSES -> FALSIFY -> SEARCH -> SIMULATE -> RANK -> EXECUTE DIFFERENT ROUTE -> READBACK -> REGRESSION -> VALUE -> LEARN -> PREVENT RECURRENCE`

The lesson may be persisted only on an authorised user-controlled surface and must be read back before durable-learning claims.

## 15. Human-First / SOVARA integration

## 23. Terminal condition

A visual mission is complete only when the requested design family exists at the proven scope, has been read back, passes fidelity/proof/privacy/authority QA, and all remaining provider, runtime, publication or value gaps are explicitly stated.

The governing question is:

**What does this visual allow the owner or audience to see, understand, decide or remember that the original information did not make sufficiently obvious?**

If the answer is nothing, redesign it.
