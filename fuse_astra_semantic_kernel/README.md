# FUSE Astra+ Semantic Kernel v0.2 candidate

This package implements the executable core of the FUSE Astra+ v2.3 architecture pivot: a small semantic cognitive microkernel, whole-route capability compiler, evidence-learning challenger advisor, and adaptive cognition governor.

## Design rule

Canonical capability identity is semantic. Historical `IH-*` numbers are aliases only and may be ambiguous. The compiler fails closed on ambiguous aliases and unknown canonical capabilities.

## Compile order

1. Freeze mission/profile requirements.
2. Resolve canonical semantic capabilities.
3. Apply hard authority, residency, safety, quality, maturity and proof gates.
4. Remove disallowed providers when the profile requires Astra independence.
5. Generate compatible whole-route combinations rather than greedily optimizing each capability in isolation.
6. Enforce route-level cost, latency, evidence-confidence, provider-concentration, locality, owner-intervention and failure-risk constraints.
7. Reduce survivors to a Pareto frontier.
8. Apply owner preference weights only to the already-qualified frontier.
9. Optionally nominate a shadow challenger from verified historical outcomes; learning never auto-promotes or bypasses gates.
10. Execute separately; provider/local readback, evaluation and proof still determine maturity.

## Adaptive cognition

`cognition.py` converts uncertainty, novelty, failure cost, irreversibility, contradiction density, tool complexity, latency pressure, privacy requirements and deterministic fit into a FUSE-owned cognition plan. It can select deterministic code, local models, value-provider models, frontier cognition, or an ensemble/judge topology. High latency pressure never suppresses high-risk verification, and privacy can force a local-first route.

This is the functional FUSE analogue of provider reasoning-effort controls: the policy belongs to FUSE even when a particular processor does not expose native low/medium/high/xhigh/max settings.

## Evidence-learning routing

`learning.py` records externally scored route outcomes and uses bounded uncertainty only to nominate already-policy-qualified Pareto challengers for shadow/matched evaluation. It deliberately does **not** let an adaptive/bandit mechanism change the incumbent by itself. Promotion remains the responsibility of the external Evolution/Proof court.

## Current proof boundary

The package has deterministic unit coverage for:

- preservation of conflicting historical aliases;
- unambiguous semantic identity;
- proof/authority gates before economics;
- Astra-independent routing rejecting OpenAI-only implementations;
- cross-capability compatibility tags;
- route-level provider-concentration and local-sovereignty constraints;
- evidence-confidence and failure-risk treatment;
- Pareto-frontier preservation of real tradeoffs;
- evidence-learning challenger nomination without auto-promotion;
- deterministic-vs-model cognition allocation;
- high-risk verification floors and privacy-local bias.

It does **not** claim live provider parity, production routing, model-weight ownership, or deployment maturity. Those require FUSE provider/local readback and lane-specific parity courts.

## Canonical planes

`CK.STATE`, `CK.CONTEXT`, `CK.MODEL`, `CK.TOOL`, `CK.EXEC`, `CK.IDENTITY`, `CK.POLICY`, `CK.AGENT`, `CK.OBSERVE`, `CK.EVAL`, `CK.PROOF`, `CK.ARTIFACT`.

## North-star invariant

Astra may be the strongest current processor for a workload, but Astra is never the mission state, memory system, policy authority, execution substrate, evidence ledger, or proof authority. A lane earns `ASTRA-INDEPENDENT` only after an alternate/local route satisfies the same frozen functional contract and evidence court.
