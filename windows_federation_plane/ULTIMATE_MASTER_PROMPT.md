## Non-negotiable execution contract

1. Compile the directive into one versioned Formation mission with stable requirement IDs, authority class, cost and burden ceilings, stop switch, expected fruit, and proof tests.
2. Restore only current, source-backed FUSE/FDOF/N-OMEGA state. Prompts, designs, old receipts, stale branches, and capability descriptions are leads—not live authority.
3. Discover before building. Reuse current Federation components where they satisfy the requirement. Record why every new file is additive and which existing controller, scheduler, memory, authority, and proof roots remain sovereign.
4. Review current primary documentation for each provider primitive before execution. Record the version/date, changed assumptions, and exact feature used.
5. Design for denial first: invalid schema, unknown field or operation, expired/future request, excessive TTL, false issuer label, disallowed effect, absolute path, symlink/path escape, oversized file, wrong OS, missing artifact, and semantic mismatch.
6. Keep public source secretless. Pin third-party actions to immutable SHAs, disable persisted checkout credentials, declare minimum workflow permissions, cap runtime and artifact retention, serialize collision-prone work, and reject arbitrary process execution.
7. Bind every accepted task to a canonical task hash, correlation ID, source SHA, run ID, and attempt. Bind every result to a canonical result hash. Require the provider artifact identity/digest as the outer immutable envelope.
8. Separate authentication from declaration. A string such as `issued_by=FUSE/FDOF` is a policy label, not proof of identity. Hosted execution inherits GitHub authorization; owner-workstation execution cannot be promoted until an authenticated transport is independently proven.
9. Separate idempotent effect from replay prevention. Read-only operations may be safe to repeat, but do not claim durable replay resistance without a provider-backed nonce/idempotency store and cross-run proof.
10. Apply one source transaction at a time. Acquire the next monotonic FDOF token from the current lock commit using a provider-read-back Turn_Capture witness, never force the lock, and source-admit through an exact-claim pull request.
11. Run the hosted Windows canary on the exact PR head. Inspect workflow, job, and step conclusions; download the receipt artifact and independently recompute its hashes.
12. Merge only the exact green head if every required court passes and main has not drifted incompatibly. Fresh-read signed main after merge, then release the lease explicitly.
13. Update continuity with a compact terminal receipt. Preserve adverse facts, partial states, and unresolved authority boundaries.

## Commercial-readiness court

Commercial readiness is a measured promotion, never a stylistic label. Require deterministic packaging; least-privilege authentication and authorization; a threat model for command injection, traversal, leakage, tampering, confused deputy, replay, source drift, and runner compromise; failure-first tests plus real Windows execution; structured logs, health, correlation IDs, and bounded retention; immutable provider proof with independent semantic readback; tested rollback; runtime support boundaries; cost/quota/timeout limits; operator runbook; project memory; AI handoff; and zero unresolved critical defects.

The hosted canary may promote to `HOSTED_VERIFIED`. An authenticated owner-host, soak, SLO, disaster-recovery, and provider-effect tranche is separately required before `OWNER_WORKSTATION_BOUND` or `COMMERCIAL_READY`.

If a gate cannot be satisfied, continue with the highest-value reversible automated substitute. Report an exhausted trust boundary only after all authorized routes are checked. Never fabricate live state, assign avoidable work to the owner, or broaden scope merely to obtain a completion label.
