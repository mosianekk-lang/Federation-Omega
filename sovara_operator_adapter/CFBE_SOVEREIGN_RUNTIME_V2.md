# CFBE-Ω v2 — Sovereign Federation-Native Runtime

## Status

`SOURCE_FORMED / PROVIDER_NEUTRAL_CORE / OPERATIONAL_INDEPENDENCE_PROOF_BOUND`

This document defines the public-safe architecture for elevating CFBE-Ω from a
chat-hosted benchmark loop into a Federation-native control service. It does not
claim that every provider adapter is live, that a 24x7 external runtime has been
deployed, or that platform-independent operation is already proven.

## Constitutional position

CFBE-Ω is a peer Federation control node. ChatGPT, Gemini, Google Cloud, Google
Apps Script, GitHub Actions, Microsoft surfaces and future providers are
execution, retrieval, critique or verification adapters. None is the CFBE
memory root, authority root or canonical state owner.

The invariant is:

`OBJECTIVE + CANONICAL STATE + PROOF -> SOVEREIGN CORE -> ADAPTER ROUTE -> EFFECT -> INDEPENDENT READBACK`

A surface may disappear without erasing CFBE state. A new surface may be
admitted without changing CFBE semantics. No adapter inherits authority merely
because it can execute a tool call.

## Six planes

1. **Sovereign Core** — deterministic benchmark, audit, opportunity, resource
   sufficiency, foresight and route-selection semantics. Pure code must not
   require a provider SDK.
2. **Canonical State Plane** — Kim Dataverse, Federation Bible Fabric, CFBE
   Bible/knowledgebase and immutable source/proof pointers. Model memory is a
   convenience cache only.
3. **Knowledge Plane** — frontier sources, standards, benchmark history,
   estate intelligence, gap/debt state, 50-move horizons and learnings.
4. **Execution Mesh** — bounded adapters for ChatGPT, Gemini/Vertex, Google
   Cloud, Apps Script, GitHub Actions, Drive/Gmail, Microsoft and future
   providers.
5. **Independent Verification Plane** — an executor cannot certify its own
   material effect. Verification must be semantic, action-bound and sourced
   from a distinct verifier route where required.
6. **Failover & Formation Plane** — objective-preserving failover scans current
   authorized routes before declaring incapability. Missing non-owner
   capability follows discover -> reuse -> extend -> repurpose -> compose ->
   form/build -> test -> canary -> independent readback.

## Adapter contract

Every adapter snapshot must expose, without raw secrets:

- stable adapter identity and surface class;
- capability set;
- current presence/freshness;
- read/write/authority ceiling;
- provider-execution state separate from control-plane reachability;
- incremental cost class;
- reversibility/rollback support;
- semantic-readback support;
- evidence/proof reference and truth boundary.

Adapters are ranked only for the current objective. Stale, absent,
insufficient-authority, unknown-cost or provider-unverified routes fail closed
when the mission requires those properties.

## Platform-independence maturity

CFBE uses four proof-bound states:

1. `CONTROL_PLANE_NEUTRAL` — canonical design/state no longer requires a host
   model, but no non-ChatGPT execution proof is claimed.
2. `CORE_PORTABLE_NON_CHATGPT_PROVEN` — the same core is executed successfully
   by at least one non-ChatGPT runtime with exact source/test proof.
3. `MULTI_SURFACE_EXECUTION_PROVEN` — the same objective/core has successful
   execution proof across at least two distinct surface classes, including a
   non-ChatGPT surface.
4. `SURFACE_INDEPENDENT_OPERATIONAL` — multi-surface proof plus a real semantic
   failover/recovery sequence shows that one surface can fail while CFBE
   preserves state/objective and completes through another authorized route.

Architecture, source presence, CI admission or connector inventory alone may
not promote CFBE to the final state.

## Secret sovereignty

The sovereign core rejects raw credential-shaped fields. Stable provider
secret names/references, project IDs, service identities and non-secret route
handles may be used as capability references. Trusted provider runtimes resolve
secret payloads transiently. Raw values must not be placed in public source,
ordinary ledgers or chat context.

## Failover semantics

A route failure is not objective failure. The core removes the failed adapter
from the current candidate set and recomputes the strongest authorized route.
Failover may not increase authority, cost or consequential scope. When all
admissible routes are exhausted, the residual dependency is recorded exactly
and independent work continues.

## Fifty Moves Ahead and opportunity mining

The Unified Capability Graph, High-Scale Opportunity Radar and rolling 50-move
horizon are provider-neutral state inputs. A platform may help generate,
challenge or execute a move, but it does not own the horizon. Material surface,
proof, mission, cost, authority, failure or frontier changes invalidate stale
future assumptions and trigger recomputation.

## First portability proof route

The first non-ChatGPT proof target is the repository's existing Federation
Omega Airlock GitHub Actions lane. No new workflow is added. The canonical
sovereign-core regression suite is bound through the already admitted
`test_phoenix_provider_cutover_v3*.py` pattern. Successful CI proves only that
the provider-neutral core executes outside ChatGPT; it is not yet proof of
24x7 provider service or semantic cross-surface failover.

## Promotion gates

A sovereign-runtime promotion requires:

- exact-source identity;
- deterministic regression suite;
- secret-free public source;
- existing Airlock/Leak Guard/Bubbles admission;
- non-ChatGPT execution receipt;
- canonical state/readback continuity;
- second-surface execution for multi-surface state;
- actual forced/observed failover plus independent semantic verification for
  `SURFACE_INDEPENDENT_OPERATIONAL`.

No benchmark score, Bible declaration or task prompt can substitute for those
proofs.
