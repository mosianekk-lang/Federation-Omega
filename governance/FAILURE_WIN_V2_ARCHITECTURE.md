# Failure-to-Operational-Win v2

Failure-to-Operational-Win v2 is an in-place AO-HARMONIC/Federation extension, not a new sovereign system.

## Control loop

`DETECT -> PRESERVE -> CLASSIFY -> RECALL -> MODEL_CAUSES -> FALSIFY -> SEARCH_CAPABILITIES -> SIMULATE -> RANK_ROUTES -> AUTHORIZE -> EXECUTE -> READBACK -> REGRESSION_TEST -> SOAK -> SCORE_VALUE -> LEARN -> DIFFUSE -> PREVENT_RECURRENCE`

Prevention path: `PREDICT_PRECURSOR -> PREWARM -> AVOID_FAILURE -> VERIFY_VALUE`.

## Reused Federation capabilities

The implementation composes AO-HARMONIC EventBus, Omega-Scientia, Horizon-Omega, FederationDigitalTwin, FormationEngine, ResourceMarket, RealityGuard, Omega-AUTOFIX/CFRE, AdaptiveCycleEngine, PerformanceVector, ProofGraph, SemanticReadbackFirewall, EvidenceOps, TruthGrid, Sentinel, JARVIS, CFBE, ChatBridge and the pre-revenue cost governor.

## New v2 mechanics

- system-specific and portable Failure Genome fingerprints;
- competing causal hypotheses and falsification ranking;
- dynamic receiver-attestation manifest instead of a fixed system count;
- bounded recovery-route race using materially different eligible routes;
- multi-dimensional improvement gate with protected quality, reliability and proof floors;
- stage-specific time budgets with hard commitments preserved;
- repair-oscillation detection and route quarantine;
- machine-checkable bounded-win and operational-win proof graph;
- repeated-success and soak requirements;
- precursor-driven prewarming and prevention metrics.

## Promotion boundary

Canonical registration is not behavioral adoption. `BOUNDED_WIN` requires the complete bounded proof graph. `OPERATIONAL_WIN_VERIFIED` additionally requires repeated successes and soak. Estate-wide promotion also requires a complete current receiver manifest in which every receiver has its own current invocation, behavioral proof and independent readback evidence.

The kernel makes decisions only. Provider/runtime effects remain the responsibility of an independently authorised execution surface and require separate readback evidence.

## Migration

The original `PROP-FAILURE-WIN-20260822-002` remains historical predecessor evidence. v2 is admitted through normal source controls, then registered as the in-place successor. Receiver coverage is regenerated from the live Federation registry rather than copied from the historical 20-system RealityGuard adapter. Receivers are promoted separately after their own canaries.
